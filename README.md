# Уют — как всё это устроено и как этим пользоваться

Сайт для учёта продуктов дома, вишлиста и растений, с синхронизацией между устройствами и уведомлениями в Telegram.

## Ссылки

- **Сайт**: https://nnrpi.github.io/uyut-site/
- **Код (GitHub)**: https://github.com/nnrpi/uyut-site
- **База данных (Firebase Console)**: https://console.firebase.google.com/project/uyut-site/database/uyut-site-default-rtdb/data
- **Уведомления (Cloudflare Worker)**: https://dash.cloudflare.com/ → Workers & Pages → `uyut-notify`
  - Публичный адрес воркера: https://uyut-notify.ropai-anna.workers.dev/
- **Telegram бот**: `@home_keeper_anya_kolya_bot` (называется HomeKeeper), сидит в группе "дом"

## Как пользоваться сайтом

Просто открывай https://nnrpi.github.io/uyut-site/ с любого устройства (телефон, комп) — данные одни на всех, хранятся в Firebase, не в браузере.

- **Продукты**: кнопка "+" → название, картинка или эмодзи (можно выбрать из большого списка) → Добавить. Статус меняется через выпадающий список под карточкой: Есть / Кончается / ALARM!!!.
- **Вишлист**: то же самое, только текст без картинок.
- **Цветочки**: суккулент и драцена — фиксированные, добавить/удалить нельзя. Клик по фото — загрузить/сменить своё. Клик по статусу переключает Полит / Не полит.

## Как устроено технически

1. **Сайт** — один файл `index.html`, лежит в GitHub-репозитории `nnrpi/uyut-site`, ветка `main`. GitHub Pages сам публикует его по адресу выше при каждом пуше в `main` (обычно 30–60 секунд).
2. **База данных** — Firebase Realtime Database (бесплатный тариф). Все данные (продукты, вишлист, растения, фото) хранятся в узле `/uyut` этой базы. Правила доступа сейчас открытые (`.read: true, .write: true`) — то есть теоретически любой, кто узнает адрес базы, может там что-то поменять. Для личного некритичного использования это ок, просто не выкладывай ссылку на базу публично.
3. **Уведомления** — Cloudflare Worker `uyut-notify`. Код лежит в файле `cloudflare-worker.js` в репозитории (для истории — сам Cloudflare этот файл не читает, код нужно руками вставлять в дашборде).
   - Работает по расписанию (Cron Trigger) каждые 5 минут.
   - При срабатывании: читает базу, сравнивает текущие статусы продуктов/растений с тем, что запомнил в прошлый раз (хранится в `/uyut/_notifyMeta`), и если что-то поменялось — шлёт сообщение в Telegram.
   - 1 и 15 числа каждого месяца дополнительно сам сбрасывает статус суккулента на "Не полит" и уведомляет об этом.
   - Токен бота и chat_id хранятся в Cloudflare как секреты (Settings → Variables and Secrets), в коде и в гите их нет.

## Как редактировать код сайта

Код лежит на компе в `~/uyut-site/index.html`. Изменения делаются так (это делает Клод, но для справки):

```bash
cd ~/uyut-site
# правим index.html
git add index.html
git commit -m "какое-то сообщение"
git push
```

После пуша через 30–60 секунд сайт обновится сам на GitHub Pages.

## Как поменять телеграм-чат или бота

Если понадобится подключить уведомления к другому чату:

1. Добавь бота `@home_keeper_anya_kolya_bot` в нужный чат (или сделай нового бота через `@BotFather`, если нужен новый токен).
2. Напиши в чате любое сообщение (например `/start`), чтобы бот его увидел.
3. Узнай chat_id: открой в браузере
   `https://api.telegram.org/bot<ТОКЕН БОТА>/getUpdates`
   и найди там `"chat":{"id": ...}` — это и есть chat_id (для групп он отрицательный).
4. В Cloudflare: `uyut-notify` → Settings → Variables and Secrets → поменяй `TELEGRAM_CHAT_ID` (и `TELEGRAM_BOT_TOKEN`, если бот новый) → Save and Deploy.

### Важная особенность: "обычная группа" превращается в "супергруппу"

Если в Telegram-группе меняются какие-то настройки (права участников, включаются определённые функции), Telegram может автоматически превратить её в супергруппу — и **chat_id при этом меняется**. Если уведомления вдруг перестали приходить:

1. Проверь напрямую, жив ли бот и чат:
   ```
   curl -X POST "https://api.telegram.org/bot<ТОКЕН>/sendMessage" -d chat_id=<СТАРЫЙ CHAT_ID> -d text="тест"
   ```
2. Если в ответ придёт ошибка вида `"group chat was upgraded to a supergroup chat"` с полем `migrate_to_chat_id` — это и есть новый chat_id. Обнови секрет `TELEGRAM_CHAT_ID` в Cloudflare на это новое значение.

## Как проверить, что уведомления вообще работают

Не обязательно ждать 5 минут — можно дёрнуть воркер вручную, открыв в браузере:
https://uyut-notify.ropai-anna.workers.dev/

Если там написано `ok` — скрипт отработал без ошибок. Сообщение в Telegram придёт, только если с прошлого прогона реально что-то изменилось (иначе просто нечего слать — это нормально, не баг).

## На заметку (грабли, на которые уже наступали)

- **Firebase выкидывает пустые массивы/объекты.** Если сохранить в базу `products: []` (пусто), при чтении оттуда это поле просто пропадёт, а не вернётся пустым списком. Поэтому в коде сайта и воркера везде стоит подстраховка вида `remote.products || []`.
- **Не используй `.set()` на весь узел `/uyut`, если рядом лежат другие данные.** Раньше сайт при каждом сохранении делал `dataRef.set(data)` — это полностью стирало узел `_notifyMeta`, которым пользуется воркер для уведомлений. Сейчас сайт использует `.update()`, который трогает только свои поля (`products`, `wishlist`, `plants`) и не задевает `_notifyMeta`. Если будешь что-то менять в этой логике — не наступи на те же грабли.
- **Продукты — это массив, а не объект по id.** Чтобы поменять статус конкретного продукта напрямую через Firebase REST API, нужно обращаться по индексу в массиве (`/uyut/products/0.json`), а не по полю `id` (`/uyut/products/p12345.json` создаст мусорный элемент, а не обновит нужный).
